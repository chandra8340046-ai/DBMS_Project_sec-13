3. Databases

Using and testing both relational and non-relational databases

  • ✓ Relational Database
  • ✓ Structured Data
  • ✓ ACID Compliance
  • ✓ Best for core transactional data (users, orders, payments, etc.)
  • ✓ Managed using MySQL Workbench
  • ✓ NoSQL Database
  • ✓ Flexible Schema
  • ✓ Good for unstructured or semi-structured data
  • ✓ Useful for property metadata, reviews, or rich media content
  • ✓ Managed using MongoDB Compass
Why Both?
  • ✓ We are using both MySQL and MongoDB to test and identify which database best suits our project requirements.
  • ✓ Some data (e.g., users, transactions, enquiries) may be better stored in MySQL (relational), while other data (e.g., property listings, reviews, media) may be better stored in MongoDB (document-based).
  • ✓ This helps us compare performance, flexibility, and scalability before finalizing the database for the project.
